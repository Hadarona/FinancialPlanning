# **Project Requirements**

## **1. Development Environment**

- The project must be developed on Linux or macOS.
- Create a project directory.
- Create a `README.md` file containing a description of the project.

## **2. Version Control (Git)**

- Use Git.
- The main branch must be named `main`.
- Each feature or bug fix must be developed in a separate branch.
- Upload only the necessary files to GitHub; do not upload system files.

## **3. Testing**

- Write unit tests.

### **<u>Bonus</u>**

- Achieve at least 70% code coverage.
- Use a tool that measures the code coverage percentage.
- Perform API integration tests by testing a real server through HTTP requests, rather than testing only the function directly.

## **4. Use of Third-Party Libraries**

- Use external libraries to avoid reinventing the wheel.
- Create an `ALL_LICENSES` file listing the libraries and their licenses.
- There is no need to include the operating system or the programming language used for development.

### **<u>Bonus</u>**

- Contribute code to an open-source project.

## **5. Package Manager**

- Use a package manager.
- Include the dependency file, such as `package.json` or `requirements.txt`.
- Add the licenses of the packages to `ALL_LICENSES`.

### **<u>Bonus</u>**

- Also include `package-lock.json`, or the output of `pip freeze` when using Python.

## **6. Agile**

- Divide the project into small tasks.
- Write a user story for each task.
- Use a Kanban or Agile board.
- Show the project's progress over time.

## **7. Code Review**

- At least three major changes must undergo code review.
- Use pull requests.
- Address the review comments you receive.

## **8. Logging**

- Produce useful and clear logs.
- Log errors.
- Print at least one log message for every server request.
- For every API call, save the logs in an external file.

## **9. Security**

- Write secure code, especially when handling user input.

### **Bonus**

- Add a basic authentication mechanism using a username and password.

# **General Notes from the Presentation**

- Original project ideas are preferred, and you may obtain the instructor's approval for a different idea.
- It is recommended to use an Agile approach and progress in small steps.
- Showing progress throughout the process is preferable to submitting only a final result.
- A presentation will be held at the end of the course. In it, you will select one of the proposed ideas or present an idea of your own.
- During project development, keep a record of the ideas, tools, and methods you learned.
- The project contains mandatory and bonus components. It is recommended to complete all mandatory requirements before investing time in the bonus items.
